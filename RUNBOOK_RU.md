## Разделение внутренних данных и ёмкость E5

Новый этап с раздельными авторами для ранней остановки и выбора класса:

```bat
train_separated_research.cmd
```

Он сравнивает порядковую модель с E5 PCA64, добавление отдельных полей цитаты/документа и расширение E5 до 128/256 компонент. После первичного сравнения на одном seed контроль и выбранный на внутренних авторах вариант усредняются по трём seed. Сохранённые завершённые модели переиспользуются при повторном запуске. Не запускай два обучения одновременно. Прогресс — `check_status.cmd`, результаты — `results\separated_research\comparison.json`, график — `results\separated_research\separated_results.png`, пояснения — `IMPROVEMENT_PLAN_RU.md`.

## Оценка сохранённой модели на официальном test

```bat
evaluate_test.cmd
```

Используется замороженный ансамбль `joint_mean_bootstrap_fine`: 18 существующих бинарных CatBoost, без нового обучения. Сначала сохраняются протокол и прогнозы, проверяется воспроизведение вероятностей обученных моделей, затем рассчитываются тестовые метрики. Параметры, веса и правило классов по test не выбираются. Артефакты: `results\official_test_v3\frozen_protocol.json`, `predictions.csv`, `test_metrics.json`, `inference_audit.json`. Повторный запуск сохраняет прежнюю оценку. Этот этап использует существующие модели и локальные энкодеры; их нужно предварительно получить исследовательскими скриптами.

## Скачивание и распаковка

Скачивание и распаковка завершены. Скрипты запуска ниже нужны для повторной подготовки или восстановления после сбоя. Журналы фоновых запусков лежат в `.local/download-worker.log` и `.local/setup-worker.log`; ошибки — в соседних файлах с суффиксом `-error.log`. Успешное окончание подтверждают `.local/verified_core.json` и `.local/verified_video.json`.

Чтобы посмотреть прогресс, открыть `check_status.cmd` двойным щелчком. Полная готовность означает `stage: complete` и подтверждение распаковки обоих наборов. Наличие папки `data/posts` само по себе не означает, что скачаны все медиа.

Для запуска или возобновления скачивания открыть **`start_download.cmd` двойным щелчком**. Пароль для скачивания не требуется. Он запускает загрузчик в фоне, сохраняет частично скачанные файлы и не создаёт второй загрузчик, если первый уже работает. Окно запуска можно закрыть. Прогресс смотреть через `check_status.cmd`; журналы сохраняются в `.local`.

Если компьютер выключался либо нужно возобновить и скачивание, и автоматическую распаковку, открыть `prepare_data.cmd`: ввести пароль архива в локальном окне. Скрипт использует уже работающий загрузчик или запускает новый, проверяет SHA-256 и распаковывает наборы. Повторный запуск при работающем ожидании распаковки выдаёт сообщение `Dataset preparation is already running`. Пароль при вводе не отображается и в файлы не записывается. Окно `prepare_data.cmd` следует оставить открытым до завершения.

Состояние `stage: error` с сообщением об отсутствии прогресса 30 минут относится к ожиданию распаковки. Сам загрузчик после восстановления соединения может продолжить работу; повторный `prepare_data.cmd` восстановит ожидание распаковки. Сравнение показателя `Downloaded` в двух запусках `check_status.cmd` позволяет увидеть движение загрузки.

Для полного набора нужно скачать 164,59 ГБ. Архивы и распакованные данные занимают место одновременно; во время настройки свободного места было достаточно. На время загрузки компьютер должен оставаться включённым и подключённым к интернету.

Официальные ссылки, размеры и контрольные суммы сохраняются в `archives/manifest.json`. Файлы `.part` — незавершённые загрузки; переименовывать их вручную не нужно. Том получает окончательное имя только после совпадения SHA-256. Перед распаковкой суммы проверяются повторно.

Таблицы для первого запуска извлечены отдельно из нужных блоков архива через HTTP Range. Это позволило начать вычисления до завершения загрузки медиа. Полная проверка SHA-256 каждого тома выполняется после его скачивания.

## Семантическое обучение на E5

В этом компьютере уже установлены PyTorch 2.10.0 с CUDA 12.8 и Transformers 4.57.6; проверена работа RTX 5060. Веса E5 хранятся локально в `.tools/models/multilingual-e5-base`. Исходные тексты не отправляются в сервисы внешнего инференса. Энкодер заморожен; последующие классификаторы обучаются по разметке лабораторной.

Для повторения этапа открыть `train_semantic.cmd`, либо выполнить в cmd из папки репозитория:

```cmd
.venv\Scripts\python.exe scripts\semantic_embeddings.py --download-only
.venv\Scripts\python.exe -u scripts\semantic_embeddings.py --batch-size 32
.venv\Scripts\python.exe -u scripts\semantic_models.py
.venv\Scripts\python.exe scripts\plot_semantic_results.py
```

Готовые векторы и завершённые разбиения пропускаются. Незавершённый расчёт векторов продолжается с контрольной точки. При изменении исходной таблицы или настроек несовместимый кеш вызывает ошибку вместо молчаливого использования старых данных. Во время текущего запуска второй запуск делать не нужно; `check_status.cmd` показывает сохранённый прогресс. Окно обучения следует оставлять открытым.

Для одного разбиения у `semantic_models.py` есть `--fold 1`; для пересчёта отчёта без переобучения — `--summarize-only`. Журналы выполненного этапа: `.local/semantic-embedding.log` и `.local/semantic-training.log`. Все результаты этого этапа относятся к официальному train; отдельная финальная модель на всём train и новый официальный test здесь не запускались.

## Посты без собственного текста: диагностика, OCR и обучение

Запуск — `train_empty_text.cmd`. Он использует сохранённые модели предыдущих этапов и не запускает официальный test. Отдельные команды из папки репозитория в cmd:

```cmd
.venv\Scripts\python.exe scripts\empty_text_audit.py
.venv\Scripts\python.exe scripts\ocr_empty_posts.py --download-only
.venv\Scripts\python.exe -u scripts\empty_text_models.py --stage base
.venv\Scripts\python.exe -u scripts\ocr_empty_posts.py
.venv\Scripts\python.exe -u scripts\empty_text_models.py --stage ocr
.venv\Scripts\python.exe scripts\plot_empty_text_results.py
```

OCR обрабатывает все доступные картинки содержимого для официальных train-постов с `original_chars == 0`; аватары и отдельные логотипы компаний не входят в каталог. Используется EasyOCR 1.7.2 с русским и английским, CUDA, максимальной стороной 1600 пикселей и порогом уверенности 0,35. Числовые значения, ссылки, адреса почты, handles и фрагменты с маркерами счётчиков вовлечённости отфильтровываются. OCR-текст хранится только локально, в исключённой из Git папке результатов. Это эвристическая очистка, а не ручная проверка всех изображений.

Установленные дополнения: torchvision 0.25.0+cu128, EasyOCR 1.7.2 и OpenCV headless 4.11.0.86. Полный снимок окружения — `requirements-ocr-lock.txt`. Для установки в прежнее окружение:

```cmd
set "UV_CACHE_DIR=%CD%\.tools\uv-cache"
.tools\uv\uv.exe pip install --python .venv\Scripts\python.exe torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cu128
.tools\uv\uv.exe pip install --python .venv\Scripts\python.exe easyocr==1.7.2 opencv-python-headless==4.11.0.86 -c requirements-semantic-lock.txt
```

Веса OCR сохранены в `.tools/easyocr/models`. Из-за ошибки DNS хоста GitHub Releases использована закреплённая копия на Hugging Face; каждый файл до загрузки в PyTorch проверен по контрольной сумме из официального пакета EasyOCR. Источник, версия и SHA-256 записаны в `weights_source.json`. Повторный запуск с имеющимися проверенными весами не требует их скачивания.

Незавершённый OCR продолжает расчёт по отдельным сохранённым изображениям. Завершённый кеш и готовые классификаторы используются повторно. Проверка первых изображений доступна через `ocr_empty_posts.py --limit 20`; полный запуск подхватит этот кеш. Не запускать несколько копий одновременно. `check_status.cmd` показывает сохранённый прогресс; он сам по себе не подтверждает активность процесса.

Результаты: `results/empty_text/diagnosis.json`, `comparison.json`, `oof_predictions.csv`, `empty_text_results.png`. OCR-кеш, текстовые векторы и параметры — в `results/empty_text/ocr/`, модели — в `fold_1/`–`fold_3/`. Журналы исследовательского запуска: `ocr.log`, `training_base.log`, `training_ocr.log` в `results/empty_text/`. `empty_text_models.py --stage ocr --summarize-only` повторно собирает итоговый отчёт без обучения.

Все новые варианты меняют только прогнозы постов без собственного текста. `group_calibration` подбирает множители классов для этой группы; это изменение решающего правила, а не калибровка вероятностей. `selected_route` выбирает среди готовых правил по внутренним авторам. `balanced_route` совместно выбирает модель и множители по общему внутреннему macro-F1, с условием не ухудшать внутренний macro-F1 пустых текстов. Сохранённые конфигурации выбора находятся в `report.json`. Для применения маршрутизации нужны как новые модели, так и прежняя модель `visual_neighbors` и её преобразования признаков; её файлы сохраняются.

## Смысловая история автора: сначала текст, затем изображения

Запуск — `train_semantic_history.cmd`. Требуются завершённые предыдущие этапы E5 и SigLIP 2, поскольку новый эксперимент использует их сохранённые векторы и PCA. Команды для отдельных шагов в cmd из папки репозитория:

```cmd
.venv\Scripts\python.exe -u scripts\semantic_history.py
.venv\Scripts\python.exe -u scripts\history_models.py --stage text
.venv\Scripts\python.exe -u scripts\history_models.py --stage visual
.venv\Scripts\python.exe scripts\analyze_semantic_history.py
.venv\Scripts\python.exe scripts\plot_history_results.py
```

Первый шаг собирает собственные публикации только официальных train-авторов, включая ранние посты без меток. Ранее рассчитанные E5-векторы переиспользуются; дополнительные тексты обрабатываются локально. История каждой строки заканчивается строго раньше времени этой публикации. Посты с одинаковым временем не считаются предыдущими друг для друга.

Текстовый этап сравнивает добавление смысловой новизны с добавлением новизны и реакций похожих прошлых постов. Визуальный этап проверяет те же два набора вместе с уже рассчитанными признаками SigLIP 2. Он не извлекает новые видеокадры, не выполняет OCR и не дообучает энкодеры. Обучается CatBoost по меткам лабораторной, на прежних разбиениях по авторам.

`history_models.py --stage text --fold 1` запускает одно разбиение; `--summarize-only` обновляет отчёт по готовым разбиениям. Завершённые модели сохраняются при повторном запуске. Незавершённая модель обучается сначала, незавершённый расчёт дополнительных E5-векторов продолжается с контрольной точки. Не запускать две копии одновременно; окно обучения оставить открытым.

Статус показывает `check_status.cmd`. Журналы исследовательского запуска: `results/semantic_history/features.log`, `training_text.log`, `training_visual.log`. При ручном запуске через `.cmd` сообщения выводятся в окно. Сохранённый прогресс сам по себе не означает, что процесс сейчас активен.

Основные результаты: `results/semantic_history/comparison.json`, `oof_predictions.csv`, `history_results.png` и `.svg`. Признаки и их параметры — `features.joblib` и `features_manifest.json`. Описательные срезы по новизне и проверка числа прошлых постов — `diagnostics.json`; они не используются для подбора модели. Модели, порядок столбцов и правила выбора класса — в `fold_1/`–`fold_3/`. Для воспроизведения предсказаний нужны соответствующие PCA, схема признаков, ограничение допустимых классов и множители из `report.json`; один `argmax` исходных вероятностей не воспроизводит итоговую метрику. Все эти результаты остаются локальными и исключены из Git.

```cmd
.venv\Scripts\python.exe scripts\plot_visual_results.py
```

Первый шаг получает публичные веса модели. Второй отбирает изображения содержимого из `data/media/manifest.jsonl`, убирает дубликаты, рассчитывает векторы и объединяет их по постам. Аватары и отдельные логотипы компаний исключены. Пустые и нераспознанные изображения не удаляют пост из выборки. Готовый кеш используется повторно; незаконченный расчёт изображений продолжается с сохранённой контрольной точки. Незаконченное разбиение обучения запускается сначала, завершённые пропускаются. Не запускать две копии одновременно; окно обучения оставить открытым.

`check_status.cmd` показывает сохранённое количество обработанных картинок и завершённых моделей. Это сохранённый прогресс, а не проверка активности процесса. Журналы исследовательского запуска: `results/visual/encoding.log`, `results/visual/training.log`. При ручном запуске через `.cmd` сообщения выводятся в его окно.

`visual_models.py --fold 1` обучает одно разбиение; `--summarize-only` обновляет сравнение уже завершённых трёх разбиений. Сравнение находится в `results/visual/comparison.json`, график — `results/visual/visual_results.png`, векторы и модели — в `results/visual/`. Эти файлы исключены из Git. Числа относятся к проверке внутри официального train.

Модели используют векторы E5, признаки истории и SigLIP 2. PCA и стандартизация обучаются только на fitting-авторах. Параметры выбора класса и объединения прогнозов сохраняются в `fold_*/report.json`; без них `predict_proba().argmax()` не воспроизводит итоговый macro-F1. Классификаторы, PCA, стандартизаторы и порядок признаков сохраняются отдельно в каждом `fold_*`.

## Обучение методов из лекции

Запускать из папки `kairos-dataset` в cmd или терминале PyCharm:

```cmd
.venv\Scripts\python.exe -u scripts\lecture_models.py
.venv\Scripts\python.exe scripts\calibrate_lecture_decisions.py
.venv\Scripts\python.exe scripts\check_lecture_artifacts.py
```

Первая команда последовательно обучает модели на трёх разбиениях по авторам. Завершённые разбиения при повторном запуске сохраняются и пропускаются. Для одного разбиения можно добавить `--fold 1`; для пересчёта первичной таблицы без обучения — `--summarize-only`. Вторая команда выбирает правило принятия решения на внутренних авторах и формирует итоговую таблицу; модели заново не обучаются. Третья проверяет сохранённые файлы. Во время работающего запуска второй запуск делать не нужно.

`check_status.cmd` теперь показывает также число сохранённых результатов обучения. Надпись `partial` означает незавершённый набор результатов; сама по себе она не подтверждает, что процесс всё ещё работает. Журнал текущего запуска: `.local/lecture-training.log`.

Здесь используется только официальная обучающая выборка. SVM и Байес получают словные и символьные TF-IDF-признаки расширенного текста. Лес получает признаки содержания и истории автора. CatBoost получает и текст, и табличные признаки. Все модели обучаются по меткам `below`, `typical`, `above`; это обучение с учителем. Результаты в этой папке относятся к проверке внутри train, а официальный test первой версии остаётся в `results/maria/test_metrics.json`.

Файлы моделей возвращают вероятности классов. Для воспроизведения итогового выбора класса нужны также множители из `results/lecture_models/decision_audit/fold_1.json` (или соответствующего второго/третьего разбиения) и ограничение допустимых классов по истории. Готовый пример загрузки и применения этих параметров находится в `scripts/check_lecture_artifacts.py`.

## Развитие кандидата v2: контент, история и объединение

Запуск из папки репозитория: `train_priority_research.cmd`. Он проверяет сохранённый снимок v2, готовит новые признаки, обучает варианты и строит график. Уже сохранённые варианты не переобучаются; прерванный отдельный классификатор обучается заново. Одновременно должна работать только одна копия скрипта.

Отдельные команды для cmd/PyCharm:

```cmd
.venv\Scripts\python.exe -u scripts\priority_features.py
.venv\Scripts\python.exe -u scripts\priority_models.py --stage content
.venv\Scripts\python.exe -u scripts\priority_models.py --stage fusion
.venv\Scripts\python.exe scripts\plot_priority_results.py
```

`--fold 1` ограничивает обучение одним разбиением; `--summarize-only` пересчитывает итоговые метрики готовых вариантов. `check_status.cmd` показывает сохранённые варианты из 12 в каждом из трёх разбиений, а не активность процесса. Контрольные суммы кешей проверяются при продолжении.

Снимок `results/candidates/v2/manifest.json` фиксирует прежний `visual_neighbors`: три fold-модели, PCA, схемы, правила выбора класса, прогнозы и исходники. Это кандидат по результатам CV, а не модель, переобученная на всём train. Снимок не заменяется новым лидером автоматически. Публичные энкодеры остаются в локальном кеше по сохранённым ревизиям.

Новые артефакты находятся в `results/priority_research/`: `protocol.json`, `features_manifest.json`, отдельные E5-поля, `fold_1/`–`fold_3/`, `comparison.json`, `oof_predictions.csv` и `priority_results.png`. Новые зависимости не требуются. Тексты и изображения обрабатываются локально; скрипт не скачивает новые веса.

В каждом опыте добавляется один блок к прежнему v2. У проверки `additional_fields` обнаружено ноль новых текстов: это контроль добавления ещё 32 PCA-компонент прежнего expanded-текста, а не проверка нового содержимого. Раздельные цитата, документ и вспомогательные поля имеют отдельные PCA, обученные только на fitting-авторах. Визуальная история на этом этапе использует ранее закешированные размеченные train-посты; картинки пяти начальных неразмеченных публикаций автора пока не закодированы.

Для `constant_blend` и `adaptive_blend` отдельно обучаются текстовая и визуальная ветки с фиксированными 800 деревьями, без ранней остановки по calibration-авторам. Первая половина этих авторов служит для обучения функции веса, вторая — для выбора регуляризации и решающих множителей. Внешняя validation-группа остаётся отдельной. Не следует обучать объединение на прежних calibration-прогнозах моделей с остановкой по тем же меткам: такие ответы уже влияли на базовые модели.

Порядковый вариант — два бинарных CatBoost для `P(y>0)` и `P(y>1)` с проекцией на допустимый порядок. Это не нейросетевая реализация CORAL. Все официальные границы классов сохраняются.

## Устойчивость по seed и совместная порядковая модель

Запуск или продолжение: `train_stability_research.cmd`. Он обучает новые модели и после завершения всех трёх разбиений проверяет артефакты, строит график и обновляет этот же исследовательский отчёт. Повторный запуск пропускает сохранённые варианты; незавершённый отдельный классификатор обучается заново. Не запускать две копии одновременно.

```cmd
.venv\Scripts\python.exe -u scripts\stability_models.py
.venv\Scripts\python.exe scripts\report_stability.py
```

Для одного разбиения можно добавить `--fold 1`, для пересчёта итогов без обучения — `--summarize-only`. Сводный отчёт формируется только после готовности трёх разбиений. `check_status.cmd` показывает до 21 сохранённого варианта в каждом из них; это прогресс на диске, а не проверка активности процесса.

Результаты — в `results/stability_research/`: `protocol.json`, `fold_*/report.json`, классификаторы и схемы, вероятности, `comparison.json`, `diagnostics.json`, `artifact_audit.json`, `stability_results.png`. Новые зависимости и скачивание весов не требуются. Скрипт проверяет контрольные суммы прежних признаков, сохранённые авторские разбиения и соответствие переиспользуемых моделей.

Веса seed фиксированы как 1/3. Исследуются три seed у модели с историей цитирования, порядковой модели и их сочетания. Первая инициализация прежних двух семейств переиспользуется; у совместной модели все три обучаются заново. При продолжении нельзя менять seed, признаки или параметры в той же папке: проверка протокола остановит несовместимый запуск.

Множители классов подбираются только на внутренних calibration-авторах. Bootstrap решающего правила также использует только этих авторов и сохраняет группу постов каждого автора целиком. Он отличается от bootstrap внешних авторов для интервалов итогового качества. Подбор множителей не превращает исходные вероятности в откалиброванные вероятности; он меняет выбор класса.

## Git и локальные данные

Рабочая ветка — `sushcheva-maria`. В состав для GitHub входят исходники, тесты, зависимости, инструкции и актуальный PDF с агрегированными результатами. Для обучения данные нужно отдельно получить по правилам исходного репозитория; готовые веса в Git не публикуются.

Воспроизвести библиотеки в существующем окружении можно через локальный uv:

```cmd
.tools\uv\uv.exe pip install --python .venv\Scripts\python.exe -r requirements-lock.txt
```

Для нового компьютера сначала установить Python 3.12, выполнить `python -m venv .venv`, затем `.venv\Scripts\python.exe -m pip install -r requirements-lock.txt`.
